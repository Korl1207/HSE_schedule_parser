# HSE Schedule Mover

Синхронизирует расписание пар с `lk.hse.ru` в отдельный календарь Google Calendar. Работает по расписанию (cron/systemd) без участия человека: логинится через сохранённую SSO-сессию, тянет расписание на несколько недель вперёд, сравнивает с локальной БД и обновляет в календаре только то, что реально изменилось.

## Как работает

```
hse_schedule_mover/
├── auth.py            # логин в HSE (Keycloak SSO): сначала пробует переиспользовать
│                       # сохранённую сессию, и только если она истекла — логинится
│                       # по логину/паролю из .env
├── schedule_api.py     # запрос расписания к lk.hse.ru
├── models.py            # парсинг ответа в Lesson + хэш содержимого для диффа
├── db.py                 # SQLite: хранит пары, помечает добавленные/изменённые/удалённые
├── google_auth.py         # OAuth к Google (один интерактивный вход, дальше — по токену)
├── calendar_sync.py        # Lesson -> событие в Google Calendar, только через отдельный
│                            # календарь ("HSE Пары"), который бот создаёт сам и не лезет
│                            # никуда за его пределы
└── sync.py                  # оркестрация: fetch -> parse -> db

run_sync.py           # точка входа: расписание -> календарь (её и дёргает cron/systemd)
run_calendar_sync.py  # только календарь — для первого интерактивного OAuth-входа
```

Данные о парах в календаре:
- **Локация** — реальный адрес корпуса + аудитория для очных, "Онлайн" для дистанта
- **Описание** — тип занятия, преподаватель, группа, и ссылка на созвон (если пара онлайн)
- **Цвет** — один для очных пар, другой для онлайн
- **Напоминание** — только на первую пару дня: за 1.5 часа если очно, за 30 минут если онлайн

## Установка

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни `.env`: логин/пароль от HSE (`HSE_USERNAME`/`HSE_PASSWORD`) - используются только для первого входа, дальше скрипт держит сессию сам.

### Google Calendar

1. В [Google Cloud Console](https://console.cloud.google.com/) - новый проект → включить **Google Calendar API**.
2. OAuth consent screen → User type **External** → добавь себя (или того, чей календарь) в **Test users**.
3. Credentials -> **Create Credentials → OAuth client ID** -> тип **Desktop app** -> скачать JSON.
4. Положить как `data/state/client_secret.json`.
5. Запустить один раз вручную для интерактивного входа:
   ```bash
   python3 run_calendar_sync.py
   ```
   Откроется браузер, попросит войти и подтвердить доступ -> дальше это не понадобится, токен сохранится.

### Если `saml.hse.ru` недоступен с сервера

HSE иногда блокирует IP датацентров на уровне SSO. Если `run_sync.py` виснет на логине -> см. переменные `HTTPS_PROXY`/`HTTP_PROXY`/`NO_PROXY` в `.env.example` (нужен прокси с российским IP; `lk.hse.ru` при этом можно оставить без прокси через `NO_PROXY`).

## Запуск

Вручную:
```bash
python3 run_sync.py
```

На сервере - через systemd timer или обычный cron:
```
0 * * * * cd /opt/hse_schedule_mover && .venv/bin/python3 run_sync.py >> data/sync.log 2>&1
```

## Переменные окружения

Все - в `.env`, шаблон в `.env.example`:

| Переменная | Назначение |
|---|---|
| `HSE_USERNAME` / `HSE_PASSWORD` | Логин HSE (fallback, когда SSO-сессия истекла) |
| `WEEKS_AHEAD` | Сколько недель вперёд синкать (по умолчанию 4) |
| `DB_PATH` / `STATE_DIR` | Куда класть БД и состояние (по умолчанию `data/`) |
| `GOOGLE_CLIENT_SECRET` / `GOOGLE_TOKEN_PATH` / `GOOGLE_CALENDAR_ID_PATH` | Пути к файлам Google OAuth (по умолчанию в `data/state/`) |
| `GOOGLE_CALENDAR_NAME` | Имя отдельного календаря, который создаёт бот |
| `HTTPS_PROXY` / `HTTP_PROXY` / `NO_PROXY` | Опционально, если нужен прокси до `saml.hse.ru` |

## Будущие улучшения

Планируется добавить автообновление разных диапазонов времени, в зависимости от размера диапазона - разная частота обновления (до 1 недели). Будет добавлен механизм ручного добавления пар на случай, если преподаватель не согласует их с учебным офисом. Сделать словарь для переименования предметов, убирать лишние тэги по типу `(рус)` и `(англ)`.
